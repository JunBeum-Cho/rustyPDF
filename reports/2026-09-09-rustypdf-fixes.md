# RustyPDF 주석 안전성·드롭 좌표·내보내기 품질 수정

작성일: 2026-09-09 · 대상: 1.0.9 작업 트리

기존 분석 보고서의 F03·F04·F05와 추가 요청한 내보내기 품질 개선을 소스에 반영했다. 아래 내용은 수정 후 동작과 검증 결과이며, 기존 분석 보고서는 수정 전 상태를 기록한다.

## 반영한 변경

| 항목 | 수정 후 동작 | 주요 파일 |
|---|---|---|
| F03: 이동 후 복사본이 주석 저장소 공유 | 이동 복구 시 영구 레코드의 소유 경로를 먼저 갱신한다. 살아 있는 다른 문서의 키를 오래된 경로 연결 정보로 재사용하거나 덮어쓰는 동작을 거부한다. 읽기·복구·저장은 같은 프로세스 내 잠금으로 순서화한다. | `src-tauri/src/annotation_store.rs` |
| F04: 외부 HTML 직접 삽입 | 외부 주석 로드, 편집기 붙여넣기·드롭, 화면 표시·측정, 저장·내보내기에 공통 HTML 정제 정책을 적용한다. 글꼴·색·강조·정렬 등 텍스트 서식을 허용하고 이벤트 속성, 스크립트, 임베딩, 외부 리소스 요소와 위치 조작 CSS를 제거한다. CSP도 추가했다. | `src/annotations/sanitize.ts`, `src/annotations/AnnotationLayer.tsx`, `src/annotations/textLayout.ts`, `src/ipc/pdf.ts`, `src-tauri/tauri.conf.json` |
| F05: Retina 드롭 위치 오류 | Tauri의 물리 좌표를 해당 드롭 시점의 WebView 배율로 나눠 CSS 좌표로 변환한 뒤 페이지를 찾는다. | `src/ipc/dropPosition.ts`, `src/ipc/opening.ts` |
| 내보내기 품질 | 주석이 없으면 원본 PDF 바이트를 그대로 반환한다. SVG 주석은 PDF 배치 크기 기준 최소 600dpi에 맞춰 렌더링하며 원래 픽셀 크기보다 축소하지 않는다. 원본 PDF와 추가 텍스트·도형의 벡터 출력, 래스터 이미지의 원래 픽셀 보존 경로는 유지한다. | `src-tauri/src/pdf/annotations.rs` |
| 새 영역 캡처 품질 | 기본 요청 해상도를 192dpi에서 600dpi로 높였다. 이후 캡처하여 붙이는 이미지가 화면 확대율에 제한되지 않도록 한다. | `src/capture/capture.ts` |

HTML 정제에는 [DOMPurify 공식 문서](https://github.com/cure53/DOMPurify)의 허용 목록과 속성 훅을 사용했다. 드롭 좌표는 설치된 Tauri API의 물리 좌표 타입 및 [공식 좌표 변환 API](https://v2.tauri.app/reference/javascript/api/namespacedpi/#physicalposition)에 맞췄다.

## 검증 결과

- `npm test`: 5개 통과. 악성 HTML 제거, 한글·텍스트 서식 보존, 이미지 주석 보존, 붙여넣기 정제, 1·1.25·1.5·2·3배 화면 배율 좌표를 검사했다.
- `npm run build`: TypeScript 검사와 프로덕션 번들 생성 통과.
- `npm run tauri -- build --debug --no-bundle`: macOS 네이티브 실행 파일 빌드 통과. 결과는 `src-tauri/target/debug/rustpdf`다.
- `cargo test --locked`: 45회 통과, 실패 없음. 기존 중복 `#[test]` 때문에 고유 테스트는 44개다. 이번에 추가한 Rust 테스트는 저장소 회귀 검사 3개와 내보내기 품질 검사 2개다.
- 마지막 저장소 읽기 경로 검토 후 `cargo test --locked annotation_store::tests`를 다시 실행해 10개 모두 통과했다.
- 저장소 회귀 검사에서는 이동→복구→복사, 옛 파일명 재사용, 오래된 키로 덮어쓰기, 경로 연결 파일 기록 실패, 연속 이동, 이전 버전이 남긴 공유 연결 정보를 다뤘다.
- 품질 검사에서는 내보내기 전후 원본 이미지와 추가 이미지의 픽셀 일치, 텍스트·도형 객체 보존, 주석 없는 PDF의 바이트 일치, 원본 콘텐츠 영역의 렌더링 일치를 확인했다. 24px SVG를 144pt 크기로 배치하면 1200px로 출력되는 것도 확인했다.
- 실제 시험 PDF를 생성하고 앱이 사용하는 PDFium으로 렌더링하여 결과 PNG를 육안 확인했다. 시험 문서의 텍스트, 이미지, SVG, 도형에 잘림이나 겹침이 없었다.

## 적용 범위와 제한

- 여기서 600dpi는 SVG 이미지와 새 캡처의 해상도다. 원본 PDF 및 추가 텍스트·도형을 페이지 전체 이미지로 변환하는 방식이 아니다. SVG 자체를 PDF 벡터 객체로 옮기는 기능은 이번 변경에 포함하지 않았다.
- 이미 낮은 해상도로 저장한 이미지나 과거 캡처는 내보내기만으로 세부 정보를 복구할 수 없다. 원본 고해상도 이미지로 교체하거나 다시 캡처해야 한다.
- 캡처에는 기존 전체 페이지 렌더링의 3,200만 픽셀·최대 변 길이 제한이 적용되므로 페이지 크기에 따라 실제 해상도는 600dpi보다 낮을 수 있다. SVG 출력이 6,400만 픽셀을 넘으면 해상도를 몰래 낮추지 않고 크기 조정을 요청하는 오류를 반환한다. 고해상도 출력은 파일 크기·메모리·처리 시간을 증가시킬 수 있다.
- 과거 버그로 이미 한 저장 레코드에 합쳐지거나 덮어써진 주석의 개별 이력은 자동 복원할 수 없다. 기존 공유 연결은 유효 소유자 한 곳으로 제한해 추가 공유를 막는다.
- 검증 환경은 macOS Apple Silicon이다. 실제 다중 모니터 드래그, 전체 WebView 편집·보안 E2E, Windows/Intel 실행은 이번에 검증하지 않았다. 시험 PDF의 보존 검사는 모든 PDF·글꼴의 동일 출력을 보증하지 않는다.
- 수정은 작업 트리에 반영했으며 설치된 앱의 교체·배포는 수행하지 않았다.
